# grilling — 拷问式访谈（纪律型，Model-invoked）

来源：mattpocock/skills 的 `grilling` 原语（grill-me / grill-with-docs / triage / wayfinder / improve-codebase-architecture 五个编排 skill 共用的底层纪律）。核心信条：**"No-one knows exactly what they want"**（Pragmatic Programmer）——错位是软件开发最常见的失败模式，拷问在动手前消灭它。

## 何时用

- 用户拿出计划/设计/方案，要求评审、推敲、挑毛病
- 执行前需确认方向、枚举选项（对应 core.md「高影响先出 Plan」的 Plan 阶段）
- 用户描述模糊但已明确「要做」，需要把设计树问全再动手

## 不适用（边界）

- 代码已交付的审查 → `code-review-master`（那是审 diff，这是审意图）
- skill 体系盘点/清理 → `skills-system-audit`
- 一句话能澄清的语义问题 → 直接问，不进流程

## 标准流程

### Step 1 — 还原设计树（退出条件：树已落盘）

把对方的计划还原成一棵**决策树**：每个节点 = 一个待定决策，每条边 = 一个选项。落盘到回复中（表格或列表）。允许还原有误——后续步骤会纠。

### Step 2 — 逐分支拷问（退出条件：每个分支有答案或显式标「未决」）

对每个分支提问，**一次一批（≤5 问），按相关度排序**（对齐 core.md「列表每组 ≤5 项」）。问题类型按优先级：

1. **边界场景**：「如果 X 为空/超时/翻倍，这条路还成立吗？」
2. **失败模式**：「这步失败时的回退是什么？」
3. **规模前提**：「数据量/并发/频次到多少时此设计失效？」
4. **未验证假设**：「这个假设有实测证据吗，还是架构直觉？」
5. **不做清单**：「哪些明确不做？」（无边界=无验收）

拷问纪律：
- 问题必须**指向决策**，不是展示知识——每个问题要能改变树的形状
- 对方答「不知道」→ 合法答案，该分支标「未决」，禁替他编答案
- 不给客套缓冲（「好问题」类禁句），直接下一个问题

### Step 3 — 收敛判定（退出条件：无「未决」或用户显式接受风险）

```
所有分支已决 → 输出定稿树 → 转入执行
存在未决分支 → 列出未决项 + 每项的默认保守取值
             → 用户确认「按默认走」或补答案后才动手
```

**未决分支默认取值原则**：选可回滚、影响面最小的一项，并在执行产物中标注该假设。

### Step 4 — 定稿输出（退出条件：定稿树可见）

输出内容：
1. 定稿后的设计树（最终版）
2. 执行中已锁定的假设清单（含每条的证据或「未验证」标注）
3. 下一步动作（单一，2 分钟内可启动）

## 防合理化表

| 借口 | 事实 |
|------|------|
| "需求够清楚了，直接动手" | 上一次「够清楚」的方案返工时，错的恰是你以为清楚的那条边 |
| "问太多显得不会干活" | 拷问的产出是定稿树，问 5 个问题是交付物的一部分，不是延误 |
| "这个分支太小不用问" | 小分支失效的排查成本在无记录时最高（同 skill-authoring-standards 逻辑） |
| "用户说继续就是都确认了" | 「继续」是对推进的授权，不是对未决分支的默认值确认 |

## 自检清单

- [ ] 设计树落盘可见（非只存在脑内）
- [ ] 每批问题 ≤5 且指向决策
- [ ] 「不知道」被记录为未决，未被编造
- [ ] 未决分支给了保守默认值且标注
- [ ] 定稿树 + 假设清单 + 下一步三件齐
- [ ] 全程零禁句（core.md 禁句清单）

## 边界/安全

- 本 skill 只输出访谈与树，**不动代码、不动配置**——执行是下一步的事
- 拷问中发现高风险决策（不可逆/生产写入），按 security.md 操作分级预警处理，不因「访谈模式」降低确认门槛
