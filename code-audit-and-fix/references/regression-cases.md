## 案例 1 · 早停门（P0 触发后不输出优化层）

**输入**（片段模式，无 spec）：

```python
import hashlib

DB_PASSWORD = "Pr0d@2026!x"          # 第 3 行

def save_user(conn, name, pwd):       # 第 5 行
    h = hashlib.md5(pwd.encode()).hexdigest()      # 第 6 行
    conn.execute(f"INSERT INTO users VALUES ('{name}', '{h}')")   # 第 7 行
```

**实测命中集**：`PY-07`(A 模, L3)、`PY-15`(L6)、`PY-14`(L7)；叠加语义判定 `OWASP-A03` 注入、`OWASP-A02` 弱加密存储 → 全部 **P0**。

**预期输出**：
- [ ] 结论行 = `🛑 早停：存在 P0，仅输出阻断报告`
- [ ] **不出现**：维度评分表、CAC、DICE/ROI、技术债清单、修复路线图（阶段 C 被早停门跳过）
- [ ] 健康评分标 `未评估`
- [ ] 每条 P0 必带 6 要素：位置 / 证据（原代码行）/ 影响（业务后果）/ 建议（代码块）/ 规则号 / 置信度=`高`
- [ ] `PY-15` 需注明「`md5` 用于口令散列」才算 P0；若用于非安全校验和（如文件指纹）应降级——审查时要读上下文，不是见 md5 就报

**失败判定**：出现「维度评分表」或「ROI」= 早停门失效。

## 案例 2 · 证据门槛（单引擎命中必须降级）

**输入**（片段模式）：

```python
def load(path):
    with open(path) as f:          # 第 2 行
        return f.read()
```

**实测命中集**：`PY-12`（`open\s*\(` 命中 L2）。

**预期输出**：
- [ ] 命中级别 = **P2**，标注 `置信度=低` 且原文写「待验证假设」
- [ ] **不得**定 P0/P1，**不得**写「根因：资源泄漏」
- [ ] 必须说明降级理由：`with` 已闭合上下文管理器，`open(` 属模式误报
- [ ] 结论行 = `✅ 可批准`（无真实 P0/P1）

**失败判定**：把 `with` 场景报成 P1 资源泄漏 = 证据门槛失效（grep 直击未做语义确认）。

## 案例 3 · 分级呈现（P0/P1 与 P2/P3 不混排）

**输入**（片段模式）：

```python
import os
API = "sk-live-9f8e7d6c5b4a"          # 第 2 行

def get(url):
    return requests.get(url)          # 第 5 行
```

**实测命中集**：`PY-07` **A 模命中**（`api\s*[:=]` 于 `(?i)` 下匹配 `API =`）+ **B 模命中**（`sk-` 前缀）；`PY-10`（`requests.get(` 无 `timeout=`）。

**预期输出**（结构校验，逐条打勾）：
- [ ] `#### 🔴 P0` 段落内**只有** `PY-07` 一条
- [ ] `#### 🟡 P1` 段落**独立存在**，含 `PY-10`
- [ ] `#### 🟢 P2 + 🔵 参考` 段落**独立存在**（可标注「本次无」）
- [ ] 三段落之间**无交叉**：P0 段里不出现 timeout，P2 段里不出现硬编码密钥
- [ ] 注释前缀符合映射：P0=`🚨 issue (blocking):`、P1=`issue (blocking):`、P2=`suggestion:`
- [ ] 至少 1 条 `praise`

**这条是 PY-07 双模规则的活样本**：v3.6 之前 A 模只写 `(password|secret|token|key)`、且大小写敏感，`API = "sk-…"` 完全漏报。若改后本案例 P0 段为空 → PY-07 退化，立即回滚。

## 案例 6 · 标签-动词映射与自动修复边界（v3.7 新增，v3.8 改判据）

**输入**（片段模式，含四类标签各一处）：

```python
import os                       # 第 1 行  → noise/unused_import → remove
from typing import List         # 第 2 行  → noise/unused_import → remove

def wrapper(x):                # 第 4 行  → redundant/redundant_wrapper → inline
    return helper(x)

def helper(x):
    print("debug:", x)         # 第 8 行  → noise/debug_leftover → remove
    return str(x)              # 第 9 行  → redundant/redundant_cast → inline

def long_task(a, b, c, d, e):  # 第 11 行 → structure/long_parameter_list → 只建议
    try:
        conn.execute(f"SELECT {a}")   # 第 13 行 → reliability/unsafe_cast → type_guard
    except Exception:
        pass                    # 第 15 行 → reliability/missing_error_handle → guard
    return requests.get("http://x")   # 第 16 行 → reliability/missing_error_handle → add
```

**预期输出（结构校验，逐条打勾）**：
- [ ] 每条发现带四字段：`级别` + `标签` + `动作`（`remove`/`inline`/`guard`/`add`/`type_guard`/—）+ `行为变化`（无/有）
- [ ] 标签全部落在 24 标签闭集内；动作全部落在 10 动词闭集内（结构类动作为 `—`）
- [ ] **`except: pass` 判为 `missing_error_handle`（可靠性），不得判为 `empty_block`（噪声）** —— §10.9 仲裁第 1 条
- [ ] `print("debug:", x)` 判 `debug_leftover`（噪声 → `remove`），但**不得**据此认定整段无处理逻辑
- [ ] `f"SELECT {a}"` 判 `unsafe_cast` → `type_guard`（可靠性，P0/P1）
- [ ] `long_parameter_list` 判结构类 → **只出建议，不出动词，不改码**
- [ ] **自动修复清单**（判据=可逆性/语义唯一解/发布面不变/可验证，**不是**「会不会改行为」）：
  - 噪声 3 项（`unused_import`×2、`debug_leftover`）→ **可自动**（§10.5 自动列）
  - 冗余 2 项：`redundant_cast` → **可自动**（§10.5 自动列）；`redundant_wrapper` → **需人工确认**（公开 API 边界，§10.5 人工列）
  - 可靠性 3 项按「修法唯一性」分：`missing_error_handle` 的 `except: pass` 补具体异常处理（修法多解 → 人工）、`unsafe_cast` 补显式类型检查（修法唯一 → 可自动）、`hardcoded_secret` 若在片段内（改读环境变量，修法唯一 → 可自动，但属 P0 需走 §B2）
  - 结构类 1 项 → 只建议（§10.5 人工列，不改码）
- [ ] **行为变化声明**：可靠性类若自动执行 → 报告单列「改前行为 → 改后行为」+ 补「没有这次修复就会失败」的测试；不得因「会改行为」而拒绝修复
- [ ] 报告含**双视角**：级别分组（P0/P1 vs P2/P3）+ 标签统计表（5 类）+ 行为变化统计
- [ ] §10.6 四项验证未跑之前，**不得**把修复计入「已修复」计数

**失败判定**：
- `except: pass` 被判成噪声 `empty_block` → §10.9 仲裁失效
- 结构类给出主动词或直接改码 → 「结构→只建议」规则失效
- `redundant_wrapper` 被列入自动执行清单 → §10.5 分桶失效（v3.8：公开 API 边界须人工）
- 可靠性类因「会改行为」被整体排除出自动堆 → §10.5 判据迁移失效（v3.8 前的旧口径）
- 可靠性类自动执行但**未单列变更点、未补测试** → §10.6 声明要求失效
- 只出现级别视角、缺标签统计表 → §10.8 双视角失效

## 案例 7 · 三态判定与发现者/验证者分离（v4.0 新增）

**输入**（片段模式，Grep 直击一处、语义存疑一处、可证伪一处）：

```python
# 上游（app/middleware.py，同仓库）：
# @app.before_request
# def enforce_auth(): verify_jwt(request)   # 路由级鉴权已存在

def handler(user_id):              # 第 3 行
    db.query(f"SELECT * FROM users WHERE id={user_id}")   # 第 4 行 → PY-14 命中
    return render("profile.html", user=user_id)           # 第 5 行
```

**模拟发现者输出**：「L4 SQL 拼接（PY-14）→ P0 确认；L5 未校验 user_id 归属 → 水平越权 P0 候选」。

**预期输出（结构校验，逐条打勾）**：
- [ ] PY-14（L4）判 **确认**：有完整源码追溯（拼接点→execute 路径）——**但仍需验证者复核**才计入 P0
- [ ] 水平越权候选判 **已否定**：验证者发现 `middleware.py` 路由级鉴权（纵深防御已拦截）→ 记「加固建议」不记漏洞，且进报告「已否定候选」清单
- [ ] 报告含**三态统计**行：确认 [N] · 待验证 [N] · 已否定 [N]
- [ ] 报告含**发现者/验证者分离声明**（P0 是否经独立上下文证伪式复核；单会话无法执行时必须显式声明而非默默跳过）
- [ ] **未执行验证者复核的 P0 不得表述为「确认」**，只能表述为「待复核」（needs_validation 不带严重度的引申：未跑完验证流程不给终态）

**失败判定**：
- 水平越权被直接报 P0（未查上游中间件）→ 防假阳性三原则第 1 条（充分上下文）失效
- 已否定候选不落档（报告里消失）→ 三态「已否定留档」失效
- 单会话自我确认 P0 后直接标「确认」→ 发现者/验证者分离失效

## 案例 8 · 接收审查侧六步（v4.0 新增）

**输入**：用户贴来一条审查意见：「这个函数应该抽成 Service 类，用依赖注入，这样更规范。」（意见指向 `parse_config()`，全仓 grep 显示该函数只有 1 个调用方，且是 CLI 入口。）

**预期输出（结构校验，逐条打勾）**：
- [ ] **未直接改码**——意见是「正规实现」类建议，先走 VERIFY（读函数+调用方）
- [ ] 走 **YAGNI 核验**：grep 调用方 → 仅 1 处 CLI 调用 → 回复「提议不引入」并给理由（宿主 `rules/codegen.md` Ponytail 第 1 阶梯 + workflow §1.5 分诊表）
- [ ] 回复格式 = 技术理由 + 证据（调用方计数 + 现有结构描述），**无** "You're absolutely right!" / 道歉 / 客套
- [ ] 若用户坚持 → 执行时不做无关重构（保持最小 diff），且单列变更点
- [ ] 对混在意见里的真缺陷（若意见还指出某行空指针）→ 单独走 §B4 验收循环修复，不与 YAGNI 反驳混在一条回复

**失败判定**：
- 不核验直接按意见重构成 Service 类 → 六步流程失效
- 回复以附和开头（"你说得对，确实应该重构"）→ 反表演性原则失效
- 反驳时无证据（只说「我觉得没必要」）→ EVALUATE 步骤失效

## 案例 9 · 验证计划可证伪与 inconclusive 停住（2026-11-23 新增，来源 lemon-bug-analyser）

**输入**：审查候选——「`_e3_vm` 查询失败时误把『无样本』当『采集静默』上报」。验证者拿到候选后执行验证。

**预期输出（结构校验，逐条打勾）**：
- [ ] 验证前写下三字段：**prediction**（若缺陷成立，用生产环境跑一次 VM 查询必看到「失败被译成 collector_silent 证据」）、**pass_if**（复现该翻译路径）、**fail_if**（代码里已有失败≠无样本的守卫，缺陷不成立）
- [ ] 模拟验证环境无 VM 实例 → 查询必然失败 → 此时观察结果**无法区分「守卫生效」与「环境不匹配」** → 结论必须标 **inconclusive**，注明「差一次：在有 VM 的环境重跑」，归入待验证组、不给 P0/P1
- [ ] **禁止**的输出形态：写成「疑似存在，建议关注」（模糊成疑似）；或因查询失败而声称「未复现，已排除」（假排除）；或直接标 confirmed（无声降级）
- [ ] 只有 pass_if 没有 fail_if 的验证计划（如「跑一遍看看有没有」）→ 判为不合格验证，退回补 fail_if

**失败判定**：
- 环境不匹配的失败被当作「验证通过/不通过」的任一结论 → inconclusive 停住机制失效
- 输出「疑似」而不写差哪次补采、谁来补 → 与旧「待验证假设」无差别，本条未生效

## 案例 10 · impact 校准锚点（2026-11-24 新增，来源 Cloudflare security-audit-skill 一手仓库）

**输入**：三条候选，均被 40 规则扫中且落在「安全类 → P0」的机械映射上：

| # | 候选 | 源码事实 |
|---|---|---|
| A | `api/handlers.py` 读租户数据未绑 owner | 路由无鉴权依赖，任意登录用户可传他人 `tenant_id` |
| B | `cache.py` Redis `HGETALL` 未设超时 | 上游已用连接池 + 5s socket timeout 兜底，最坏退化为慢查询 |
| C | `requirements.txt` 有 1 个 CVE-2024-xxxx 的中危依赖 | 该依赖仅用于本地构建脚本，不进运行时镜像 |

**预期输出（逐条打勾）**：
- [ ] A 判 **P0**：锚点 high（完全击破显式控制 = 跨租户读，有实际后果）
- [ ] B 判 **P3 加固建议**，不判 P0：属「纵深防御缺口 / 缺最佳实践」——上游已拦（Layer A 生效），说不出「没有 Layer B 则攻击成立」的完整路径
- [ ] B 同时符合 `informational`（影响极小）与「无锚点可落」→ **后者优先**（§7.1 锚点冲突消歧：说不出攻击路径的一律 P3，不问影响大小），**不得**因「影响小」判 P2
- [ ] C 判 **P1**（中危 CVE + 不进运行时 → 真实但影响半径窄），**不得**因规则号命中就机械判 P0
- [ ] 三条均须能回答「具体损害是什么」；B 答不出 → 级别比直觉低一档（即不判 P0）
- [ ] 级别不得超过已演示 impact：A 标 critical/ high、B 标 informational、C 标 medium，不得跨档
- [ ] 每条写出 **high vs medium 判别句** 的答案（完全击破 / 只是削弱）

**失败判定**：
- B 因「安全类规则命中」被机械判 P0 → 锚点表未生效，退回纯规则映射
- C 被判 P0（等同 A）→ 缺 impact 校准，阻断信号被稀释
- 出现「medium 但级别 P0」→ 违反「级别不超过已演示 impact」

## 案例 11 · 覆盖终态与指纹稳定（2026-11-24 新增，来源 Cloudflare security-audit-skill 一手仓库）

**输入**：一轮标准审查，审了 12 个文件，主 Agent 自查后拟写「已全面审查，无遗留 P0/P1」。同时需与上一轮报告对账（上轮报过 `auth.py:88` JWT 签名跳过校验，已否定）。
