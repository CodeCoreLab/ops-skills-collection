# 修复标签体系与动词映射（§10）

> 本文件由 `SKILL.md` 按需加载（对抗档必读；标准档仅在需自动修复时读）。
> `§N` 编号与原单文件版一致（对照表见 `SKILL.md`）。

## 10.1 两轴模型：分级 × 标签（互不替代）

| 轴 | 回答的问题 | 取值 | 决定什么 |
|---|---|---|---|
| **分级轴**（§7） | 多急？ | P0 / P1 / P2 / P3 | 是否阻断合并、是否早停、验证强度 |
| **标签轴**（本节） | 怎么改？ | 噪声 / 冗余 / 重复 / 结构 / 可靠性 | 修复动作（动词）、自动化许可 |

**判定顺序**：先按 §7 定级（决定要不要动），再按 §10 打标签（决定怎么动）。
标签**不改变**级别，只改变**处置方式**。同一位置命中多标签 → 按 §1.3 聚合规则保留最高级别，标签取**主标签**（离「怎么改」最近的那个），其余作副标签并列。

**标签不是级别的替身**：一条 `hardcoded_secret`（可靠性）默认 P0；一条 `unused_import`（噪声）默认 P3。二者标签不同级别也不同，但**修复动词都由标签决定**。

## 10.2 五类标签定义与处置

**类别级默认动作（用户口径，标签级可细化但需在报告写明理由）**：

| 类别 | 类别默认动作 | 处置原则 |
|---|---|---|
| 噪声 NOISE | `remove` | 直接删 |
| 冗余 REDUNDANT | `simplify` / `inline` | 简化 |
| 重复 DUPLICATION | `extract` | 提取 |
| 结构 STRUCTURE | 仅建议 | 不改代码 |
| 可靠性 RELIABILITY | 必须修 | 行为可改变；修法唯一者可自动，多解者需人定方案 |

### 噪声类（NOISE）— 直接删（删的是确定无引用的，不动逻辑）

| 标签 | 判定标准 | 默认动词 | 自动修复 | 默认级别 |
|---|---|---|---|---|
| `dead_code` | 无任何引用方的函数/类/常量（已 grep 全仓 + 反射/字符串引用排查） | `remove` | ✅ 自动（须先过引用排查） | P3 |
| `debug_leftover` | 遗留 `print`/`console.log`/`breakpoint()`/`pdb.set_trace`/`TODO: remove` | `remove` | ✅ 自动 | P3 |
| `commented_code` | 整块被注释的代码（保留说明性注释不动） | `remove` | ✅ 自动 | P3 |
| `unused_import` | 导入后未被使用（`import`/`from`） | `remove` | ✅ 自动 | P3 |
| `unused_variable` | 赋值后从未被读取的局部变量 | `remove` | ✅ 自动 | P3 |
| `empty_block` | 空 `pass`/`else:`/`except:`（**吞异常**的 `except: pass` 归可靠性，见 `missing_error_handle`） | `remove` | ✅ 自动（吞异常者按 §10.9 归可靠性） | P3 |
| `redundant_comment` | 复述代码本身、无信息量的注释（保留解释 why 的） | `remove` | ✅ 自动 | P3 |

**噪声铁律**：只删**确定无引用**的。反射、动态导入、字符串拼接调用、插件注册表、`__all__`、装饰器副作用 → 一律降为「待人工确认」，不做自动删。

### 冗余类（REDUNDANT）— 简化：压平多余的转换 / 判空 / 中转变量

| 标签 | 判定标准 | 默认动词 | 自动修复 | 默认级别 |
|---|---|---|---|---|
| `redundant_cast` | 类型已确定的多余转换（`str(str(x))`、显式转同类型） | `inline` | ✅ 自动 | P3 |
| `redundant_null_check` | 判空后立即无条件解引用（`if x is None: ... ; x.y`） | `simplify` | ✅ 自动 | P3 |
| `redundant_condition` | 恒真/恒假分支（`if True:` / `if x is not None` 且 x 必非空） | `simplify` | ✅ 自动 | P3 |
| `redundant_return` | 函数末尾多余的 `return` / `return None` | `remove` | ✅ 自动 | P3 |
| `redundant_wrapper` | 只做转发、无附加语义的包装函数 | `inline` | ⚠️ 人工（公开 API 边界，调用方不可见） | P2 |
| `redundant_variable` | 仅作一次中转的中间变量 | `inline` | ✅ 自动 | P3 |

**冗余铁律**：压平后必须**逐调用点核语义**（默认参数求值时机、副作用顺序、异常传播路径）。压平**可以改变行为**（规则 6 允许）——但行为差异必须在报告里显式声明，不得静默生效。

### 重复类（DUPLICATION）— 合并为单一真源

| 标签 | 判定标准 | 默认动词 | 自动修复 | 默认级别 |
|---|---|---|---|---|
| `code_clone` | 逐字符相同的 ≥5 行代码块（≥2 处） | `extract` | ⚠️ 人工（需人判定两块语义等价） | P2 |
| `near_duplicate` | 结构相同、仅变量名/字面量不同 | `extract` | ⚠️ 人工（同上） | P2 |
| `duplicated_logic` | 同一业务规则的第二实现（两个真源 → 漂移风险） | `merge` | ⚠️ 人工（哪份是正确语义需人判） | P2 |
| `magic_number_dup` | 同一魔法字面量散落 ≥3 处 | `parameterize` | ✅ 自动（提为命名常量） | P2 |
| `copy_paste_block` | 复制粘贴产生的整段复制（含复制来的错误） | `extract` | ⚠️ 人工（同上） | P2 |

**重复铁律**：提取前先判定**两个块语义真的等价**——边界处理、超时、日志、异常吞噬不同 → **不是重复**，强行合并必引入 bug。提取类（`code_clone`/`near_duplicate`/`copy_paste_block`）与合并类（`duplicated_logic`）**一律转人工**：需人判定哪份是正确语义、语义是否等价，不自动执行（§10.5）。

**新依赖允许，但合并需人确认**：若合并需引入新依赖（规则 7 允许），仍不自动执行——依赖引入会改 lockfile/版本约束，属发布面变更，须人工确认。

### 结构类（STRUCTURE）— 只建议，不动手

| 标签 | 判定标准 | 默认动词 | 自动修复 | 默认级别 |
|---|---|---|---|---|
| `long_function` | 单函数 >50 行（Python）/ >80 行（其他） | —（只建议，方向 `extract`） | ⚠️ 人工（只建议，不改码） | P2 |
| `deep_nesting` | 嵌套 >3 层 | —（只建议，方向 `guard`） | ⚠️ 人工（只建议，不改码） | P2 |
| `long_parameter_list` | 参数 >4 个 | —（只建议，方向 `parameterize`） | ⚠️ 人工（只建议，不改码） | P2 |

**结构铁律**：**只输出建议，不改代码**。拆分函数/引入参数对象会改公共签名与调用面，属破坏性变更 → 走 §2.2 契约核验 + 人工定稿（宿主 `rules/codegen.md §定稿纪律`）。
唯一例外：`long_parameter_list` 且**只加不删**参数（内部函数、私有方法）可按 `parameterize` 人工执行，仍不自动。

### 可靠性类（RELIABILITY）— 必须修

| 标签 | 判定标准 | 默认动词 | 自动修复 | 默认级别 |
|---|---|---|---|---|
| `missing_error_handle` | 可失败调用无处理（网络/文件/DB 调用无 try 或无 timeout）、异常被吞 | `guard` / `add` | ⚠️ 修法唯一时可自动（如「补 timeout」「补 try-except 明确异常类型」）；多解转人工 | P1 |
| `unsafe_cast` | 强制类型断言绕过检查（`as`/`# type: ignore`/`unchecked`/`!` 非空断言） | `type_guard` | ⚠️ 修法唯一时可自动（补显式类型检查）；多解转人工 | P1 |
| `hardcoded_secret` | 源码内明文口令/Token/Key/证书 | `replace` | ⚠️ 修法唯一时可自动（改为读环境变量/密文槽）；多解转人工 | P0 |

**可靠性铁律**：**必须修**。修复**可以改变行为**（规则 6 允许）——但属**行为有意变更**，必须在报告中单列变更点 + 补对应测试（§10.6）。**不是「其他四类必须等价」的例外区**，而是「行为变化必须被声明、被测试」的一类。

## 10.3 修复动词词典（10 个）

| 动词 | 含义 | 典型标签 | 行为影响 | 风险 |
|---|---|---|---|---|
| `remove` | 删除整块（死代码/注释/导入/多余 return） | 噪声全部 | 通常无变化 | 低（前提：无引用） |
| `inline` | 就地展开/压平（中间变量、冗余转换、转发包装） | 冗余 | 可能变（求值时机/副作用顺序） | 中 |
| `simplify` | 化简条件表达式（去恒真/恒假、去冗余判空） | 冗余 | 可能变（边界语义） | 中 |
| `extract` | 提取为独立函数/常量/模块 | 重复、结构 | 通常无变化（调用面可能变） | 中（公共签名面） |
| `merge` | 合并两处实现为单一真源 | `duplicated_logic` | 可能变（选哪份为准） | 高（业务语义分歧） |
| `replace` | 用新实现替换（密钥→环境变量/密文槽） | `hardcoded_secret` | **变**（凭据读取路径） | 高（凭据/调用方） |
| `add` | 补齐缺失的处理（try/except/timeout/校验） | `missing_error_handle` | **变**（异常路径新增） | 中 |
| `guard` | 前置守卫（early return / fail-fast / 断言） | 可靠性、结构 | **变**（提前终止路径） | 中 |
| `type_guard` | 用类型守卫/显式校验替代不安全断言 | `unsafe_cast` | **变**（分支新增） | 中 |
| `parameterize` | 魔法值/长参数列表参数化 | `magic_number_dup`、结构 | 通常无变化（魔法值）/ 可能变（参数对象） | 低 / 高 |

**动词选择规则**：
1. 标签已给出默认动词；**例外需在报告里写明理由**（如 `redundant_wrapper` 内部只有 1 个调用方 → `remove` 而非 `inline`）。
2. 行为是否改变**不构成自动执行的禁区**（规则 6 允许）——禁区的判据是**「改错不可逆 / 需人判定正确语义 / 破坏发布面」**，见 §10.5。
3. 一个修复点只用**一个**主动词；需要复合时（如「提取常量 + 替换调用点」）主词取 `extract`/`parameterize`，副动词在备注里写。
4. **行为有意变更的修复点**（`replace` / `add` / `guard` / `type_guard` / 可能变体的 `inline`/`simplify`/`merge`）→ 报告必须单列变更点并补测试（§10.6）。

## 10.5 自动修复安全边界

**判据迁移（v3.7 → v3.8）**：规则 6 改为「可改变行为」、规则 7 改为「可引入新依赖」后，**「会不会改变行为」「会不会引入新依赖」不再是自动执行的禁区判据**。改用四条**独立判据**（任一不满足 → 转人工）：

| 判据 | 含义 | 不满足 → |
|---|---|---|
| **可逆性** | 改错能靠版本控制一次回滚 | 转人工 |
| **语义唯一解** | 修法只有一种正确答案，无「二选一」的业务判断 | 转人工 |
| **发布面不变** | 不改公共 API 签名 / 导出符号 / 依赖版本约束 / lockfile | 转人工 |
| **可验证** | 有现成手段判定改对改错（编译 / 测试 / 探针） | 转人工 |

| 允许自动执行 | 需人工确认（出方案不改码） | 不可自动执行（红线） |
|---|---|---|
| 噪声类全部：`dead_code`（需先过引用排查）· `debug_leftover` · `commented_code` · `unused_import` · `unused_variable` · `empty_block`（吞异常者按 §10.9 归可靠性）· `redundant_comment` | `redundant_wrapper` → `inline`（公开 API 边界，调用方不可见） | 删除**公开 API / 导出符号**（破坏发布面且调用方不可见） |
| 冗余类：`redundant_cast` · `redundant_null_check` · `redundant_condition` · `redundant_return` · `redundant_variable` | `code_clone` · `near_duplicate` · `copy_paste_block` → `extract`（需人判定两块语义是否真等价） | 生产环境写入 / 删数据 / 改凭据投放（不可逆） |
| `magic_number_dup` → `parameterize`（提命名常量） | `duplicated_logic` → `merge`（哪份是正确语义需人判） | 单次修复跨越 >10 个文件（回滚粒度过粗） |
| 可靠性类中**修法唯一**者：`missing_error_handle`（补 timeout / 补 try-except 明确异常类型）· `unsafe_cast`（补显式类型检查）· `hardcoded_secret`（改为读环境变量/密文槽） | 可靠性类中**修法多解**者：`missing_error_handle` · `unsafe_cast` · `hardcoded_secret`（异常该吞还是该抛、该 catch 哪个类型、失败该降级还是该中止） | 需改依赖版本约束 / lockfile（发布面变更，即使规则 7 允许引入新依赖） |
| — | 结构类全部（规则 4：只建议）：`long_function` · `deep_nesting` · `long_parameter_list` | — |

**自动执行的附加前置**（缺一不可）：
1. 工作区无未提交改动（或已单独提交）→ 便于回滚
2. 引用排查已完成：全仓 grep + 反射/动态引用/字符串调用排查（`dead_code`/`unused_import` 必做）
3. 修复后立即跑验证（§10.6）
4. 单批 ≤10 个修复点，超出转人工

**行为变更不阻断自动执行，但必须声明**：可靠性类修复（补错误处理、改凭据路径）本就改变行为——按规则 6 允许自动执行，条件是变更点在报告里单列 + 补对应测试（§10.6）。**「会改行为」不是拒绝理由，「改错了不可回滚 / 不知道哪种才对」才是。**

**新依赖不阻断自动执行，但发布面变更转人工**：规则 7 允许引入新依赖。引入**第三方库并锁定版本**（改 `requirements.txt` / `package.json` / lockfile）属发布面变更 → 人工确认；**仅使用标准库**（`typing`/`dataclasses`/`pathlib` 等）→ 可自动。

**回滚**：单文件级修复点打包为一次提交（`fix: 移除未使用导入 (noise/unused_import)`），不与功能改动混提。

---

## 10.6 验证（规则 6「可改变行为」的落地）

**规则 6 的口径（v3.8）**：修复**可以改变行为**。因此验证的靶子从「证明行为没变」改为「**证明改动是想要的**」：

| 情形 | 类别 | 要求 |
|---|---|---|
| **等价性重构** | 噪声 / 冗余（多数） / 重复（提取） | 行为应当不变；若发现实际变了 → 停下并说明，**不得静默生效** |
| **有意行为变更** | 可靠性类全部；冗余/重复中确需改语义的 | **变更点必须显式声明 + 补测试**，在报告单列 |

**四项验证**（逐项过，任一不过即回滚该修复点）：

| # | 验证 | 方法 | 判定 |
|---|---|---|---|
| 1 | 语法/类型 | `py_compile` / `tsc --noEmit` / 编译 | 零错误 |
| 2 | 既有测试 | 项目测试套件（相关子集必跑） | 全绿，无新增失败 |
| 3 | 行为影响核对 | 逐点对照修复前后语义 | 行为变化**已被识别**——是预期的（有意变更）还是意外的（→ 回滚） |
| 4 | 变更面核对 | 导出符号 / 公开签名 / 依赖清单 diff | 与「发布面不变」判据一致；变了且未声明 → 回滚 |

**有意行为变更的附加要求**（可靠性类及任何语义变更点）：
1. 报告里**单列变更点**：改前行为 → 改后行为，一句话说清差异
2. **补测试**：新增行为须有「没有这次修复就会失败」的测试（宿主 `rules/codegen.md §定稿纪律`）
3. 涉及错误路径的变更 → 测试必须覆盖该异常路径（§7 测试生成原则）

**验证不通过 → 该修复点回滚**，写入报告并说明原因（例：压平改变了默认参数求值时机，且该行为变化非预期）。

## 10.7 自动修复执行顺序

```
1  收集：扫描 → 每条发现打标签（§10.2）+ 定级（§7）
2  分桶：按标签分 5 桶；按「可靠性 → 重复 → 冗余 → 噪声 → 结构」顺序处理
     （可靠性优先：先补上错误处理，再清理它周围的噪声）
3  过滤：过 §10.5 三张表 → 分为「可自动」/「需人工」/「禁止自动」三堆
     （过滤依据是可逆性/语义唯一解/发布面不变/可验证，不是「会不会改行为」）
4  自动堆：单批 ≤10 → 逐点改 → 每次改后跑 §10.6 四项验证
5  人工堆：出方案（标签 + 动词 + 预期 diff），不动码
6  汇总：报告按标签分组 + 级别分组双视角呈现（§10.8）；行为变更点单列
7  收尾：未闭环项单列，不混入「已修复」计数
```

**顺序理由**：可靠性修复会新增代码（异常处理分支），会让原先的噪声标签位置变化 → 先修可靠性，噪声判定才准确。

## 10.8 报告呈现（双视角）

**每条发现必带四个字段**：

```
- 标签：[noise/unused_import] · 动作：[remove] · 自动：[是/否] · 行为变化：[无/有（说明）]
```

**行为变化统计**（与标签统计表并存）：

| 行为变化 | 条数 | 处理要求 |
|---|---|---|
| 无变化（等价性重构） | [N] | 常规四项验证 |
| 有意变更（可靠性类等） | [N] | 单列变更点 + 补测试 |
| 意外变化 | 0 | 发现即回滚，不入表 |

**标签统计表**（进执行摘要，与 §9.2 模板并存）：

| 标签类别 | 条数 | 可自动 | 待人工 | 主动词 |
|---|---|---|---|---|
| 噪声 NOISE | [N] | [N] | [N] | remove |
| 冗余 REDUNDANT | [N] | [N] | [N] | inline/simplify |
| 重复 DUPLICATION | [N] | [N] | [N] | extract/merge |
| 结构 STRUCTURE | [N] | 0 | [N] | —（只建议） |
| 可靠性 RELIABILITY | [N] | [N]（修法唯一者） | [N]（修法多解者） | guard/replace/add |

**分组呈现铁律（叠加 §7 铁律）**：报告需同时满足两轴——级别维度 P0/P1 与 P2/P3 分组呈现；标签维度五类分组呈现。**P0/P1 组内按标签再分组**（可靠性 P0 独立成段），不混排。

## 10.9 冲突仲裁（同一位置多标签）

| 情形 | 仲裁 | 理由 |
|---|---|---|
| `empty_block` vs `missing_error_handle`（`except: pass`） | 取**可靠性** | 吞异常是缺陷，不是空代码 |
| `debug_leftover` vs `missing_error_handle`（`except: print`） | 取**可靠性**，删 print 副标签保留 | 需补 log 替代，不是纯删 |
| `dead_code` vs `redundant_wrapper` | 取**冗余**（`inline` 调用方） | 删公共转发函数会破调用面 |
| `code_clone` vs `duplicated_logic` | 取**重复**（`duplicated_logic`→`merge`） | 有两个真源 = 漂移风险 > 代码冗余 |
| `hardcoded_secret` 与其他标签同位 | 可靠性优先，**单独成条** | 凭据问题不与其他问题打包修复 |
| 噪声标签但 P0 级（例：`dead_code` 是后门入口） | **级别优先**，走可靠性处置 | 级别由 §7 定，标签不降级 |

**仲裁原则**：**级别定严重度，标签定动作**；两者冲突时级别不被标签覆盖，标签可被级别「拉高」（即升级为可靠性处置）。

## 10.10 精简原则（本节的硬约束）

- 每条规则必须满足：可执行（明确标签 + 动词 + 判定阈值）、可验证（四项验证 + 报告字段）、不模糊（禁「考虑/适当/尽量」）
- 标签**只增不改**：24 个标签（噪声 7 / 冗余 6 / 重复 5 / 结构 3 / 可靠性 3）为闭集，新增须先改本表 + 回归样例
- 动词**只增不改**：10 个动词为闭集
- 标签与级别**互不替代**：任何报告不得用标签代替级别定阻断性

### 10.11 修复动作八条硬规则（用户口径，落地位置）

| # | 规则 | 落地位置 |
|---|---|---|
| 1 | 噪声 → 直接删 | §10.2 噪声类 / §10.5 可自动列 |
| 2 | 冗余 → 简化 | §10.2 冗余类 / §10.5 可自动列 |
| 3 | 重复 → 提取 | §10.2 重复类 / §10.5 部分需人工 |
| 4 | 结构 → 仅建议 | §10.2 结构类（只建议、不改码；§10.5 人工列） |
| 5 | 可靠性 → 必须修 | §10.2 可靠性类 + §7 分级 |
| 6 | **可改变行为** | §10.6：等价性重构行为应不变；有意行为变更须显式声明 + 补测试 |
| 7 | **可引入新依赖** | §10.5：标准库可直接引入；第三方库需锁定版本（改 lockfile）→ 人工确认 |
| 8 | 保持代码风格 | 沿用现有命名/缩进/注释惯例；格式化交工具（lint/format），禁手改格式 |

**规则 6 细则**：修复**可以改变行为**——不因「会改行为」拒绝修复。约束落在**声明与验证**上：① 等价性重构（噪声/冗余/提取）行为应不变，实际变了要停下说明；② 有意行为变更（可靠性类）必须在报告单列变更点（改前 → 改后）并补「没有这次修复就会失败」的测试；③ 行为变化意外发生时 → 回滚该修复点，不静默生效。
**规则 7 细则**：修复**可以引入新依赖**。① 标准库（`typing`/`dataclasses`/`pathlib`/`enum` 等）→ 可直接引入并自动执行；② 第三方库 → 可引入，但**锁定版本**会改 `requirements.txt`/`package.json`/lockfile，属发布面变更 → 人工确认后执行，不自动跑 `pip install`；③ 引入的依赖须同步登记到依赖清单，并说明用途。
**规则 8 细则**：删代码时保留原有注释风格与分节结构；提常量时命名跟随该文件既有风格（`SCREAMING_SNAKE` vs `camelCase` 看现状）；不改与本次修复无关的格式。
