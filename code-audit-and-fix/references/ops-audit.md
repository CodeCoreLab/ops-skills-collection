## 八、运维脚本审计模式

> **触发**：用户说"运维脚本审计""脚本安全""Shell/Python 运维代码审查"时启用。

**审计重点（按踩坑频率排序）**：
1. **路径断裂**：sys.path/硬编码路径 vs 服务器实际目录（重构后最高发）；实跑或 grep 验证，不轻信注释
2. **数据源锚定**：区分真数据库与同名诱饵/空库（lsof/进程 cwd 锚定运行中服务的实际 DB）
3. **子进程泄漏**：subprocess.run 无 timeout → Popen + TimeoutExpired kill
4. **global 污染**：模块级可变全局被 import 副作用触发
5. **fail-open**：异常吞掉后继续跑（告警/推送类必须 fail-closed）
6. **密钥与凭据**：硬编码/明文/权限过宽 → 环境变量/加密

**修复流程铁律**：
- 改前备份 `cp file file.bak_YYYYMMDD`
- 复杂修改：本地构造新文件 → scp 上传 → 远端 `python3 -m py_compile` → grep 验证（禁远端 sed 处理中文/引号）
- 改后实跑验证一次最小路径
- 服务器脚本审计：先 scp 拉到本地审，**禁在服务器上直接改**
